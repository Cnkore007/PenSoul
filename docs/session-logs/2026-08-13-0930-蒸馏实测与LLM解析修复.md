# 会话日志：蒸馏功能实测 + 修复 LLM 代码块包裹系统性 bug

- 时间戳：2026-08-13 09:30 CST
- 目标：实测书籍蒸馏功能（用户要求"跑一遍测试"），验证其真实产出与价值
- 结论先行：**功能本身可用且产出质量高；但实测发现并修复了一个系统性 bug——LLM 输出被 Markdown 代码块包裹，导致蒸馏/事实提取等所有依赖 LLM 结构化输出的功能从未成功过**

## 实测过程与发现

1. 启动最新后端（旧服务停掉重启），确认语料存在（07:19 上传的《雪中悍刀行》epub，12000 字样本）
2. 调 `/api/distill/analyze`（GLM 蒸馏，约 50s）→ **失败**："蒸馏响应不是合法 JSON"
3. 加诊断日志复跑 → 原始响应为空？排查后确认是 grep 过滤假象，实际响应以 `\n\n```json` 开头
4. 用 curl 直连 GLM 中转复现 → **实锤**：`message.content` 是 ```` ```json\n{...}\n``` ````（Markdown 代码块包裹），`finish_reason: stop`
5. 全仓排查：**7 处 LLM 结构化解析点**（batch 细纲、cascade 级联×2、distill、extract 事实提取、review 审校、rewrite 改写）全部直接 `serde_json::from_str(content.trim())`，遇代码块必失败
6. 旁证：`style-recipe.json`、`operation-log.json` 均不存在 → **蒸馏与事实提取从未成功过**（用户上传语料、保存过章节，但相关功能全部静默失败；审校静默降级本地、事实提取前端提示失败）

## 修复（系统性，一处修复全部生效）

- `pensoul-infra::llm` 新增 `parse_llm_json<T>`：依次尝试 ① 直接解析 → ② 剥离 ``` 代码块围栏 → ③ 截取首个 `{` 到末个 `}` 主体；失败返回带原文前 300 字预览的错误
- 7 处解析点全部替换为 `parse_llm_json`（保留各自错误语义，错误信息现在包含解析原因与原文预览）
- 新增 4 个单测（纯 JSON / ```json 包裹 / 包裹+前后文字 / 非法输出带预览）

## 验证结果

- `cargo test --workspace`：111 通过 / 0 失败（infra 26 含新增 4 个）
- 修复后重跑 `/api/distill/analyze`：**成功**——7 维度 + 5 写作基因 + 10 禁用清单，47s，落盘 `data/_config/style-recipe.json`
- `get_recipe` API 正常返回配方；配方注入链路（writing.rs:153 / review.rs:111 `recipe_injection_text`）代码核实存在

## 配方产出质量评估（《雪中悍刀行》12000 字样本）

- 词汇指纹：市井粗口与文言雅句并置、人物称谓体系化、具象名词高精度（黄酱桂皮老姜八角/绣冬春雷红螭）等 5 条
- 句法节奏：中国式长句堆叠、单句独立成段"断剑式"收尾、破折号双声道等 5 条
- 修辞/叙事/悬念/母题各维度均给出**可执行**特征（如"扮猪吃虎是核心叙事范式"、"章末必留钩子"）
- 禁用清单 10 条含明确反 AI 味价值（"禁止'眼中闪过一丝不易察觉的XX'式 AI 味微表情描写"）
- 结论：提示级蒸馏达成设计预期（"像谁"），无原文摘抄（版权红线遵守）
