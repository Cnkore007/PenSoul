# 会话日志：拉取模型的文档定位与参数提取

- 时间戳：2026-08-09 22:50 CST
- 目标：按用户澄清——对「从供应商拉取的模型列表」中的每个模型，定位其官方接口文档，抓取后提取详细参数，可一键导入配置并详细编辑

## 关键决策与取舍

1. 文档定位：`suggest_model_doc_url(doc_url, model_id)` 按 `{文档根}/models/{模型ID}` 规则构造；优先使用配置中的 doc_url，其次按供应商默认文档站（OpenAI/Moonshot/DeepSeek/Anthropic）构造；用户也可在请求中手动覆盖
2. 参数提取：新增 `extract_model_params(html, model_id)` 启发式提取器——查找 "context window/上下文窗口" 等模式后的 `Nk/1M` 规模、`max output/最大输出` 后的 token 数、thinking/reasoner 标识；文档中直接出现的规模标识（1m/256k/200k/128k/64k/32k）自动转为上下文窗口候选；提取不到的字段返回"未识别"，由用户人工确认
3. 详细参数扩展：配置新增 `stop_sequences`（逗号分隔转数组）、`json_mode`（response_format）、`thinking_budget`（DeepSeek thinking.budget_tokens）、`timeout_seconds`（5~600，默认 120）；`LlmRequest`/`build_chat_body` 同步支持，测试调用携带全部详细参数
4. 前端链路：拉取模型列表 → 每个模型「文档与参数」按钮 → 展示建议文档地址、标题/描述/预览、提取参数（窗口/输出/思考模式/notes）与本地保存路径 → 「导入参数并建档」把提取结果填入新增表单 → 详细参数可继续编辑
5. 兼容性：`ProviderConfig` 新增字段用 `#[serde(default)]` 保护旧配置文件反序列化

## 遗留事项与待验证假设

- 参数提取是启发式：JS 渲染的文档页静态文本可能不含规模数字，提取不到时界面显示"未识别"，需人工从文档预览确认；后续可接入供应商结构化 API 或专用解析器
- `thinking` 参数格式按 DeepSeek 官方 API（`{"type":"enabled","budget_tokens":N}`），其他供应商兼容性待真实调用验证
- 模型列表拉取仍依赖用户配置的真实密钥
