# 会话日志:知识库化重构 P0/P0b/P1 落地

- 时间:2026-08-13 01:10
- 类型:功能改造(前后端)
- 依据:docs/design/2026-08-13-知识库化重构设计.md(已冻结)

## 任务目标

按冻结设计实施前三个阶段:
- P0b:Agent 注册表 + 按角色选模型(写作/审校/提取/细纲/蒸馏 各自可绑定不同 LLM)
- P0:档案化——人物档案字段(外貌/衣着/功法/境界/法宝)、组织档案实体、图谱知识库页、侧边栏合并(删蓝图/人物/世界,笔耕移到大纲下)
- P1:事实提取管线(全自动:保存后自动提取 Fact 包 → 写档案 → 冲突告警 → 操作日志)

## 关键决策与取舍

- **P0b 角色回退设计**:AgentConfig 绑定 llm_config_id,None = 回退全局默认(向后兼容);配置存 `_config/agent-config.json`(全局,预留 project_overrides 供作品级覆盖);writing/review 改为 `agent::resolve(role)`;新角色(提取/细纲/蒸馏)随模块接入。
- **P0 组织档案**:Entity 枚举加 Organization 变体(编译器强制所有 match 补全:评估器/记忆评分/摘要/描述);ontology.world.organizations(serde default 兼容旧项目);人物新字段 attire/techniques/realm/items。
- **侧边栏合并**:ViewType 删 blueprint/character/world;页面文件保留但不再引用(其能力已并入图谱/大纲);图谱页重构为「类型 tab + 搜索 + 详情编辑」(人物/组织完整表单,事件/设定/伏笔占位)。
- **P1 全自动安全阀**:用户拍板全自动;实现为保存成功后前端自动调用 extract-facts(不阻塞保存);后端 LLM 提取(Extractor 角色)结构化 Fact → 应用(同名跳过/追加去重/伏笔推进)→ full_audit 硬约束告警 → 操作日志(_config/operation-log.json,最近 500 条)。Fact 应用是真实写正典 + rebuild_derived。

## 可复用经验

- Entity 枚举加变体后,编译器会列出所有非穷尽 match(评估器/记忆/图谱),逐个补分支即可,是安全的扩展方式。
- "全自动写正典"的安全阀三件套(冲突审计告警 + 同名跳过 + 操作日志)平衡了体验与一致性。
- 保存后前端 fire-and-forget 触发后台任务(extractFacts.then)比后端 tokio::spawn 简单可靠,且不阻塞保存。
