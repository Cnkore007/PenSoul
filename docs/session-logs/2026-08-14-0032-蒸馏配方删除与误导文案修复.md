# 会话日志：蒸馏「配方记录」无法删除修复 + 误导文案澄清

- 时间戳：2026-08-14 00:32 CST
- 任务目标：用户手动测试发现「风格蒸馏」页无法删除已经蒸馏的记录，并质疑「蒸馏为什么那么快、是不是没有真正分析」。查清事实并补齐删除能力。

## 排查结论

1. **「无法删除」的根因**：语料行本身有删除按钮且删除生效（`distill-corpus.json` 已为空）；真正删不掉的是「当前配方」（`style-recipe.json`）。后端只有 `DELETE /api/distill/corpus/delete`，**没有删除配方的接口**，前端也没有入口。
2. **蒸馏是真实实现**：`analyze` 会对每本书做全本六段采样（上限 6 万字符），POST 到绑定 Distiller 角色模型（当前 glm-5.2，走 tokenhub）的 `/v1/chat/completions`，解析 JSON 后落盘配方，不是本地假分析。昨日实测约 47-50s。
3. **「快」的真相**：今天配方文件的 `generated_at` 仍为 2026-08-13 10:02，且今天只在 00:26:27 被「强度滑块」（`update_recipe`，不改 `generated_at`）写过一次。因此用户看到的配方是昨天蒸馏的旧结果，今天并未真正重跑 `analyze`；上传语料只是本地落盘（瞬间完成），上传成功文案还写着过时的「自动采样至多 1.2 万字」，进一步造成「上传即已分析」的误解。

## 改动

- 后端新增 `DELETE /api/distill/recipe/delete`（`commands/distill.rs::delete_recipe`）：删除当前项目配方文件，文件不存在时幂等返回成功；`api.rs` 注册路由。
- 前端 `ipc.ts` 新增 `deleteStyleRecipe()`；`SettingsView.tsx` 配方区新增「删除配方」按钮（二次确认，删除后刷新为空）。
- 删除语料时若该书已参与当前配方，确认框给出提示（删语料不会连带移除配方，需删除配方或重新蒸馏）。
- 修正上传成功文案：由「自动采样至多 1.2 万字」改为「已保存全本，点『开始蒸馏』时才调用模型做全本多点采样分析」。

## 跨页面排查

- 同一 SettingsView 的兄弟标签页均已有删除/回滚出口：配置管理有「删除」、日志与归档有「回滚/压缩」，仅蒸馏页缺少配方删除，已补齐。未发现其他同模式缺口。

## 验证结果

- `cargo check --bin pensoul-server` 通过；`cargo test --workspace` 111 个用例全过。
- `npx tsc --noEmit` 通过。
- 重启后端后实测 `DELETE /api/distill/recipe/delete`：未打开项目时返回 400「没有打开的项目」（证明路由已注册、handler 已接管，非 404）。
- `cargo fmt --check` 存在全仓既有格式漂移（api.rs 等历史文件），非本次引入；本次新增代码沿用所在文件现有风格，未做全仓重排。

## 遗留事项与待验证假设

- 真正的端到端删除留待用户在页面上点「删除配方」验证（后端重启后需重新进入项目）。
- 当前配方引用的语料已被删光、配方已过期，建议用户删除后重新上传并蒸馏。
