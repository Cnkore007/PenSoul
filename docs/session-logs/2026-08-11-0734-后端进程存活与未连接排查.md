# 后端进程存活与「后端未连接」排查

- 时间：2026-08-11 07:34
- 主题：打开 web 客户端需前后端一起启动；后端进程中途退出导致页面显示「后端未连接」

## 任务目标

1. 执行用户语义：说「打开」= 前端 + 后端一起启动，缺一不可
2. 排查页面显示「后端未连接」的根因

## 关键决策与取舍

- **`cargo run` 后台任务不可靠**：用 Bash 工具 `run_in_background` 启动的 `pensoul-server` 进程，启动后某时刻被回收/退出（日志无报错、进程消失、3001 无监听），是「后端未连接」的根因。
- **改用 `nohup` 常驻启动**：`cargo build --bin pensoul-server && nohup ./target/debug/pensoul-server > /tmp/pensoul-server.log 2>&1 &`，进程脱离任务生命周期，可长期存活。日志落 `/tmp`，不进仓库。
- **「后端未连接」是真实状态而非误报**：前端 `src/ipc.ts` 统一走 `/api` 相对路径，由 Vite 代理转发到 `127.0.0.1:3001`；后端挂掉 → Vite 代理返回 500 → `src/views/ProjectsView.tsx:14` 的 `listProjects()` 抛错 → `setMsg("后端未连接")`。curl 直连/代理对比（HTTP 000 / 500）能快速定位「是后端挂了」还是「前端探针错」。

## 改动文件

- `AGENTS.md`：新增「本地开发启动（用户语义约定）」小节——「打开 = 前端 Vite(1420) + 后端 pensoul-server(3001) 一起启动」；后端源码有改动时用 `cargo run`/重新构建，不能用过期二进制。
- 无前端/后端代码改动。

## 验证结果

- 后端常驻进程监听 `127.0.0.1:3001`，`GET /api/projects` 直连返回 200 + `[{"project_id":"project-msm1wauz10dovf","title":"移山"}]`
- Vite 代理 `http://localhost:1420/api/projects` 返回 200 + 同一数据
- 浏览器刷新页面后：原来「后端未连接」+「暂无项目」变为显示项目「移山」（带打开/删除按钮），状态「就绪」

## 遗留事项与待验证假设

- **前端无自动重试**：`ProjectsView`（及 `EntityGraphView`）只在挂载时请求一次，后端挂了再起来不会自动恢复，必须手动刷新页面；页面在渲染瞬间若后端未就绪，会永久显示「后端未连接」直到手动操作。待验证是否值得加"重试/手动刷新"能力而非一次性探针。
- 待验证：`nohup` 常驻后端跨多轮会话是否稳定存活（已观察当前存活）。
