# 会话日志：后端重启后恢复上次打开的项目，修复「没有打开的项目」

- 时间戳：2026-08-14 00:38 CST
- 任务目标：用户上传语料时报 `语料上传失败: {"error":"没有打开的项目"}`。根因是后端重启后内存中的「当前打开项目」被清空，而前端页面仍停在项目内，项目级接口全部失效。

## 根因

- 打开项目的状态只存在于后端内存（`AppState.ontology`），没有持久化；`cargo run` 重启后必然丢失。
- 前端 `currentProject` 是 React 内存态，页面不刷新就仍认为项目开着，于是上传语料等依赖 `current_project` 的接口返回 400「没有打开的项目」。

## 关键决策与取舍

- 选择在后端持久化「上次打开的项目 id」（`data/_config/last-project.json`），启动时自动 `load_project` 恢复，而非在前端做「报错后重开重试」：后端恢复一处生效，覆盖所有项目级接口，且符合本地单用户写作工具的恢复预期。
- 恢复失败（项目已删除/损坏）时静默忽略，不阻断服务启动；删除项目时若它是上次打开的项目，同步清除持久化记录。

## 改动文件

- `crates/pensoul-app/src/state.rs`：新增 `last_project_path` / `load_last_project_id` / `save_last_project_id` / `clear_last_project_id` 与 `AppState::restore_last_project`。
- `crates/pensoul-app/src/commands/project.rs`：`open_project` 成功后持久化项目 id；`delete_project` 删除上次打开项目时清除记录。
- `crates/pensoul-app/src/main.rs`：`AppState` 创建后调用 `restore_last_project` 并打印恢复日志。

## 跨页面排查

- 该问题影响所有依赖 `current_project` 的接口（蒸馏、大纲、笔耕、事实提取等），属后端全局状态丢失，后端启动恢复一次性覆盖，无需逐页修补。

## 验证结果

- `cargo check --bin pensoul-server` 通过；`cargo test --workspace` 111 个用例全过；`npx tsc --noEmit` 通过（本次无前端改动）。
- 实测：重启后端 → `POST /api/projects/open`（正常链路，落盘 last-project.json）→ 再次重启 → 启动日志输出「已恢复上次打开的项目: project-msm1wauz10dovf」→ `GET /api/distill/corpus/list` 直接返回 200，无需重新打开。

## 遗留事项与待验证假设

- 上次项目持久化记录在首次「打开项目」后才生成；此前从未打开过项目的机器重启后仍无项目可恢复，属预期行为。
- 前端页面刷新后仍会回到作品库需手动进入项目（前端 `currentProject` 未持久化），本次未改前端，属既定交互。
