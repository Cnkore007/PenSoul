# 会话日志：LLM 全局配置模块

- 时间戳：2026-08-09 22:17 CST
- 目标：用单一模块管理全局 LLM 配置，支持新增、删除、测试、拉取、上下文检测、模型文档与详细参数

## 关键决策与取舍

1. 统一配置存储：新建 `pensoul-infra::llm::config`，所有供应商/模型/密钥/参数集中存于 `data/_config/llm-config.json`（原子写）；废弃旧的 `api-keys.json` 分字段结构
2. 安全：接口返回的配置一律脱敏（`api_key_masked` 只保留头尾 4 位，`has_key` 只表达是否存在）；完整密钥只在测试调用时从存储读取
3. 配置条目支持详细参数：上下文窗口、最大输出、思考模式、流式、temperature/top_p/frequency_penalty/presence_penalty、文档链接、备注、启用状态
4. 默认配置：`default_provider_id` 全局默认，删除默认项时自动清空
5. 上下文检测：CJK 按 1 字 ≈ 1 token、其他字符按 4 字符 ≈ 1 token 估算，对照 90% 输入预算给出 `fits` 与占用百分比
6. 模型档案：内置 7 个模型（Moonshot/DeepSeek/OpenAI/Anthropic），每个带官方文档链接、说明、默认参数与输入预算
7. `LlmRequest` 扩展 `top_p`/`frequency_penalty`/`presence_penalty`，测试调用使用配置内保存的详细参数

## 改动文件

- 新增：`crates/pensoul-infra/src/llm/config.rs`（Provider/ProviderConfig/LlmConfig/LlmConfigStore + 测试）、本日志
- 修改：`llm/mod.rs`（移除 ApiKeys，导出新模块）、`llm/models.rs`（档案扩展）、`llm/client.rs`（请求参数扩展）、`commands/llm.rs`（重写 CRUD/测试/上下文检测/档案）、`api.rs`（6 条 LLM 路由）、`pensoul-app/Cargo.toml`（uuid）、前端 `types.ts`/`ipc.ts`/`SettingsView.tsx`（重做）、`tests/api.rs`（+2 集成测试）
