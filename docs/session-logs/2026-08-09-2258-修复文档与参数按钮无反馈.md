# 会话日志：修复文档与参数按钮无反馈

- 时间戳：2026-08-09 22:58 CST
- 目标：修复「文档与参数」按钮点击"没有反应"的问题

## 根因

- 用户配置为 custom 供应商（tokenhub 中转，kimi-k3），`doc_url` 为空，后端无法自动定位文档，返回 400
- 错误只显示在页面顶部的小字 `msg` 区域，点击处无任何反馈，用户感知为"没有反应"

## 修复内容

1. 后端：custom 供应商按模型前缀归一化推断文档站——`kimi-/moonshot-` → Moonshot、`claude-` → Anthropic、`gpt-/o1-/o3-` → OpenAI、`deepseek-` → DeepSeek；仍无法定位时错误消息给出 Kimi 文档参考地址
2. 前端：「文档与参数」改为面板化三态交互——点击立即在面板内显示"正在定位并抓取官方文档…"；失败时面板内直接显示错误并提供手动填写文档地址 + 「重试抓取」；成功后显示参数、预览与「导入参数并建档」
3. 合并重复的抓取 handler，去除按钮 disabled 卡死风险

## 验证结果

- `cargo test --workspace` 42 个测试全过；clippy 零警告；`tsc` 与 `npm run build` 通过
- 实证：对用户真实配置（tokenhub/kimi-k3）调用 `/api/llm/docs/model`，自动定位到 Moonshot 文档站并抓取成功，本地保存 `data/_config/llm-docs/kimi-k3.html`
- 后端已重启（127.0.0.1:3001），前端热更新

## 遗留

- 抓取到的文档含 JS 渲染内容，参数提取可能"未识别"，需人工确认；发现 Moonshot 提供 `/docs/llms.txt`（面向 LLM 的文档索引），后续可优先利用该索引精确定位模型文档页
