# 萌芽页改为对话式创作工作台

## 任务目标

把「萌芽」从固定表单改为对话式创作工作台：用户输入想法与设定，LLM 以多视角参与讨论、整理、追问；对话成熟后可生成「世界观 + 核心概念 + 大纲」结构化提案，用户确认后才写入正典。

## 关键决策与取舍

- **建议制落地**：LLM 生成的是 `pending_proposal`，不直接写入；用户点「确认写入正典」后才应用（`/api/sprout/apply`），拒绝则只丢弃提案（`/api/sprout/discard`）。
- **对话历史入正典**：`NovelOntology` 新增 `soul_sprout` 字段（`#[serde(default)]` 兼容旧项目），随项目文件持久化，刷新不丢；消息截断到最近 100 条，防止项目文件无限膨胀。
- **多视角讨论**：参考 PenSoul 专家蒸馏术（多视角评审）理念，MVP 内置「综合 / 结构 / 人物 / 世界观」四个视角，由系统提示词切换；后续可对接 `Experts/` 专家卡。
- **统一 LLM 链路**：所有调用走 `pensoul-infra::llm`，复用默认配置的模型与参数；未配置默认 LLM 或缺少 API Key 时返回明确指引。
- **锁策略**：LLM 调用期间不持有 `RwLock`，先克隆上下文与历史，调用成功后统一落盘 user + assistant 消息，失败不留半截对话。
- **应用策略**：核心概念只覆盖非空字段，世界观规则按内容去重追加，大纲脉络跳过章节范围非法的项，最后统一 `rebuild_derived + save_project`。

## 验证结果

- `cargo test -p pensoul-domain -p pensoul-app`：全部通过（23 项）。
- `npx tsc --noEmit`：无类型错误；vite 对 ConceptView 编译正常。
- 接口实测：会话返回空、无提案应用返回明确错误、拒绝与清空正常、未配置 LLM 时返回「请先到设定 → LLM 配置」指引；测试项目已删除。
- 后端已重启（新二进制运行中），前端热更新。

## 遗留事项与待验证假设

- 未配置默认 LLM 时无法端到端验证真实对话与提案生成，需用户配置 API Key 后试用；JSON 提案解析有单元测试兜底。
- 「多视角」目前是系统提示词实现的通用视角，尚未接入 `Experts/` 蒸馏出的专家卡；后续可在视角按钮中加载专家库。
- 提案应用目前采用「合并追加」策略，未提供覆盖式重写；如需整体替换世界观，后续可加「清空后应用」选项。
