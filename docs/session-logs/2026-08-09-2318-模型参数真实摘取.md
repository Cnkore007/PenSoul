# 会话日志：模型参数真实摘取（llms.txt + Markdown 表格）

- 时间戳：2026-08-09 23:18 CST
- 目标：修复「导入参数并建档」参数不准的问题，真正从官方文档摘取模型参数

## 根因

- 之前的参数提取只对抓取的页面做通用正则扫描；文档站多为动态渲染或首页不含模型规格，导致提取为空或误报（如 kimi-k3 主文档中的 80000 无关数字），导入时回落默认值

## 修复内容

1. 文档发现：新增 `fetch_llms_index`（候选 `/docs/llms.txt`、`/llms.txt`、`/zh-cn/llms.txt`，兼容根路径以 /docs 结尾）+ `parse_markdown_links` + `pick_relevant_pages`（模型专属页 > 模型列表页 > 定价页）；`fetch_model_doc` 现在会先走索引发现，主文档直接指向模型专属页（如 kimi-k3-quickstart.md）
2. 结构化摘取：`parse_markdown_table_row` + `find_model_description` 从模型列表页（models.md）表格中精确摘取该模型描述；模型列表页为权威来源，直接覆盖主文档的启发式猜测；描述含"思考/推理/thinking"时标记思考模式支持
3. 中文规模解析：`extract_context_from_description` 支持 "100 万 token"、"256k"、"128K"；修复小数误报（"2.8 万亿参数" 不再解析为 8 万）
4. 聚焦提取：`extract_model_params` 优先在模型 ID 附近 ±300 字符内查找，避免无关数字污染
5. Markdown 标题：`extract_doc_info` 对 .md 源文件用首个 H1 作为标题；.md 文档按 .md 扩展名保存以保留表格结构
6. 修复中文文本字节边界 panic（切片越界）
7. 前端：文档面板显示「摘取来源」链接列表

## 验证结果

- `cargo test --workspace`：45 个测试全过（新增表格解析/中文单位/链接排序测试）；clippy 零警告；`tsc`/`npm run build` 通过
- 端到端实证：kimi-k3 → 自动发现 kimi-k3-quickstart.md + models.md，摘取到「100 万 token 上下文窗口」→ 上下文窗口 1,000,000、思考模式 True、备注含模型列表页原文；修复过程中复现并修复了 80000 误报与字节边界 panic
- 后端已重启（127.0.0.1:3001），前端热更新
