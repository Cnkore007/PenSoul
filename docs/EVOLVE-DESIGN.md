# PenSoul × AlphaEvolve：进化式创作优化设计方案

> 最后更新：2026-08-02
> 定位：设计提案（未动代码）。落地任何一层前需用户确认，并同步 `docs/ARCHITECTURE.md`。

## 一、AlphaEvolve 是什么（调研速览）

AlphaEvolve 是 Google DeepMind 2025 年 5 月发布的**进化式编码 Agent**（arXiv 2506.13131，FunSearch 与 AlphaTensor 的继任者）。核心机制一句话：

> **LLM 集成当"变异算子"，自动评估器当"自然选择"，进化循环当"搜索引擎"。**

运转方式：

1. **候选池**：把待优化对象（代码、提示词、规则、参数）表达为可 diff 的文本；
2. **变异**：Gemini Flash（广度、便宜）+ Gemini Pro（深度、贵）双模型集成，对候选提出变体；
3. **评估**：**全自动评估器**给每个变体打分（可级联：便宜测试先过滤，贵的后跑）；
4. **选择**：MAP-Elites 质量-多样性算法 + 岛屿种群，保住"高分"也保住"不同方向的高分"，防早熟收敛；
5. **反馈侧信道**：错误/评分细节回灌进下一代的变异提示词，逐代修正。

一年生产实测（DeepMind 2026-05-07 官方回顾）：Borg 调度持续回收 Google 全球 0.7% 算力、FlashAttention GPU 内核提速 32.5%、Spanner LSM 压缩写放大降 20%、4×4 复数矩阵乘法 56 年来首次改进（48 次标量乘法）、50 余个公开数学问题中 75% 复现最优、20% 改进。目前仍为 Early Access 限定；**开源平替 OpenEvolve（6.8k★，Apache-2.0）已实现全部核心机制**：MAP-Elites、岛屿迁移、任意 OpenAI 兼容 API、级联评估、提示词进化示例（HotpotQA +23%）。

**成立的三个前提**（也是判断"能不能用在 PenSoul"的标尺）：

| 前提 | 含义 |
|---|---|
| 候选可文本化 | 优化对象必须能写成文本/代码，变体可 diff、可版本化 |
| 评估可自动化 | 必须存在无需人参与的打分函数，且分数与真实目标足够相关 |
| 预算可承担 | 进化 = 成百上千次"生成+评估"，需要明确成本上限 |

**明确不适用**：目标是"整体更好"但没有自动代理指标的场合。小说正文的艺术质量本身不可自动评分——这是本方案"**进化脚手架，不进化正文**"的根本原因。

## 二、为什么 PenSoul 是少见的"天然适配"

多数写作工具做不了 AlphaEvolve 式优化，因为它们既没有自动评分器，也没有可进化的小型产物。PenSoul 恰好两者都有，而且是指架构级自带：

| AlphaEvolve 需要什么 | PenSoul 已经有什么 |
|---|---|
| 自动评估信号 | 审查分（0-100）、黄金三章 hook/payoff 分、反 AI 味规则分（0-100）、一致性 5 规则违规数、门控通过率、单章重试次数、token 成本 |
| 可进化的小型文本产物 | 技法卡（`WritingCard/*/SKILL.md`）、审查/写作提示词、工作流模板绑定（模型 × 技法卡 × 门控阈值）、记忆预算分配参数、章前策划节拍表模板 |
| 人类真值（校准用） | 人工门控放行/打回记录、笔耕批注的采纳/拒绝、版本回滚行为——这些都是"人类裁判"的免费标签 |
| 适应度历史底座 | WAL（`.harness/`）、`harness-event` 事件流、门控事件——每次评分明细已落盘 |
| 变异执行层 | `llm_helper` 统一多模型调用 + `llm_profile` 模型档案，天然支持"便宜模型广撒、贵模型深挖"的双档集成 |
| 防 AI 自作主张的哲学 | 门控与"建议制"原则——进化产物默认只是候选，晋升走人工门，与 "AI 无权跳步" 完全同构 |

**关键洞察**：PenSoul 现有的「写作经验沉淀」（采纳批注归类入库、注入后续审查）已经是一个**只有变异、没有选择**的原始学习循环——经验只会累积不会淘汰。AlphaEvolve 思想补上的正是缺失的那一半：**用自动评估器做选择，让好的变体存活、差的淘汰**。

## 三、进化对象优先级矩阵

按"评估器可信度 × 单次评估成本 × 收益"排序，**从上到下即建议的落地顺序**：

| # | 进化对象 | 自动评估器 | 单次成本 | 风险 | 优先级 |
|---|---|---|---|---|---|
| 1 | **审查量规/审查提示词** | 人类标注章集上的判决一致率（采纳/打回、批注命中） | 低（只对标注集跑审查，不写正文） | 过拟合标注集 | ★★★★★ |
| 2 | **反 AI 味词表与规则权重** | 真人文本 vs AI 文本语料的分类准确率 | 极低（规则检测，零 LLM 调用） | 误伤人类风格化表达 | ★★★★★ |
| 3 | **写作技法卡**（SKILL.md 卡组） | 沙盒回放：审查分 + 反 AI 味分 + 一致性违规数的复合分 | 中（需写正文） | 刷分（Goodhart） | ★★★★ |
| 4 | **工作流绑定/模型路由**（环节×模型×卡） | 门控一次通过率 + 质量分 + 成本的多目标 Pareto | 中 | 模型 API 差异干扰归因 | ★★★ |
| 5 | **记忆预算/上下文组装参数** | 单位 token 的审查分增量 | 中 | 与技法卡效果纠缠 | ★★★ |
| 6 | **章前策划节拍表模板** | 下游写作一次通过率 | 高（需完整跑两段） | 评估链路长、噪声大 | ★★ |

不列入进化对象：**章节正文本身**（无可靠自动评估）、**一致性 5 条安全规则**（安全件只允许人工演进）、**门控阈值语义**（防 AI 伪造评分的硬约束不动）。

## 四、总体方案：四层落地，评估器先行

AlphaEvolve 的一切价值都建立在评估器可信之上，所以本方案把**评估器加固放在第一层，不达标不启动进化**。

### L0 评估器加固（前置，约 1-2 周）

- 建**人工标注校准集**：从既有项目抽样 200-500 章，每章记录人类判决（放行/打回 + 理由 + 反 AI 味人工分）。笔耕批注历史可直接转化为部分标签。
- 量化现有自动评分与人类判决的一致率（Cohen's Kappa / 准确率 / 误放率）。**门槛：一致率 ≥ 0.8 才允许该信号进入适应度函数**；不达标的信号只能做参考特征，不能做选择压力。
- 产物：`data/evolve/calibration/`（标注集 + 一致性报告），标注工具可先用脚本 + 表格。

### L1 离线进化沙盒（PoC 主战场，零生产风险）

- **章料回放（corpus replay）**：候选变体只在沙盒里对历史章节/标注集跑，不碰任何线上项目数据；产物全部落 `data/evolve/`（种群库、代数日志、最优候选），gitignore。
- 循环：父代采样（精英 + 多样性）→ LLM 集成变异（kimi/deepseek/glm 便宜档广撒 + 高档深挖，走 `llm_helper`）→ 级联评估（规则信号先过滤，LLM 审查后跑）→ MAP-Elites 入格。
- 多样性维度建议：`(文风保守度, 张力导向, 节奏快慢)`——保住"不同写法方向上的高分卡"，而不是收敛到单一"平均分最高的平庸卡"。
- **预算熔断**：每轮进化设 `max_iterations` 与 `max_cost_usd` 双上限（参考 OpenEvolve 实测：Flash 级模型约 $0.01-0.05/代，Pro 级约 $0.08-0.30/代）。

### L2 影子模式（线上对照，只记录不干预）

- 沙盒胜出的候选与现役配置**并行双跑**真实管线：正式产物照常，影子产物只打分落日志。
- 对照指标：审查分、一次通过率、反 AI 味分、一致性违规、成本。跑满约定章数（建议 ≥ 30 章）后出对照报告。

### L3 受控晋升（人工门 + 一键回滚）

- 晋升决策**永远是人工门**：对照报告呈给用户，用户确认后候选才替换现役技法卡/提示词/绑定。
- 技法卡与提示词均为版本化文件，天然支持一键回滚；晋升事件写入 WAL 与 PROGRESS.md。
- 灰度策略：先单项目单卷启用 → 观察 → 全量。

## 五、技术架构：先外挂、后内生

### 5.1 PoC 阶段：OpenEvolve sidecar（建议，1 周内可验证）

- 用 `pip install openevolve` 起 Python 子进程，PenSoul 侧只提供两样东西：
  1. **初始程序**：如现行审查提示词全文；
  2. **评估器脚本**：调用 PenSoul 导出的标注集，回跑审查逻辑，返回 `{"score": 一致率}`。
- 优点：MAP-Elites、岛屿、级联评估全部现成，模型走任意 OpenAI 兼容 API；验证思想成本低。
- 边界：OpenEvolve 进程**只读** `data/evolve/` 与标注集导出件，不接触 `api-keys.json`（密钥经环境变量注入，不落任何文件）。

### 5.2 产品化阶段：`pensoul-evolve` crate（PoC 验证后）

新增第 12 个 crate，复用现有基建，不外挂 Python：

```
pensoul-evolve/
├── population.rs    # 种群库：MAP-Elites 格 + 岛屿 + 谱系（父→子 diff）
├── mutate.rs        # 变异集成：走 llm_helper 双档模型，附 artifact 反馈（上代评分明细）
├── evaluate.rs      # 评估器插件接口：规则信号（反AI味/一致性）+ LLM 信号（审查）级联
├── fitness.rs       # 复合适应度 + 硬约束（安全规则违规 = 直接淘汰，不做软扣分）
├── budget.rs        # 迭代/成本双熔断 + 取消令牌（复用 pipeline 的 select! 中断模式）
└── promote.rs       # 候选 → 影子 → 人工门晋升，全程 WAL
```

复用点：`llm_helper`（多模型调用与重试降级）、`harness` 门控（晋升门 = Conditional 门控的人工批准通道）、WAL/blake3（种群快照与崩溃恢复）、`pensoul-concurrency`（候选版本管理）。

**复合适应度示例**（技法卡进化）：

```
fitness = w1·审查分 + w2·反AI味分 + w3·门控一次通过率 − w4·千token成本
硬约束（任一命中即淘汰，不参与加权）：
  - 一致性 5 规则任一严重违规
  - 标注集上的安全误判（把人类明确打回的章节判为放行）
```

### 5.3 防古德哈特（Goodhart）与防演化走偏

学术界的教训必须前置（"Your Agent May Misevolve"，arXiv 2509.26354：自优化系统安全性可在数十代后突然崩塌）：

1. **留出人评集（held-out）**：校准集切 20% 永不参与适应度，每 N 代用它在幕后复测——适应度涨而留出集不涨 = 在刷分，立即停轮。
2. **安全信号只做硬约束**，不给软分，防止"用文风分换一致性"。
3. **蜜罐章节**：回放语料中掺入埋有已知硬伤的章节，候选若系统性放过即淘汰。
4. **双上限熔断 + 谱系可回溯**：每个候选带父代 diff，出问题可精确定位是哪一代变异引入。
5. **AI 无权跳步**：进化系统自身也受门控哲学约束——它能提案，永远不能自行晋升。

## 六、首个 PoC 建议：审查量规进化

选它做第一个，因为它满足"评估最可信 × 成本最低 × 收益最直接"：

- **初始程序**：现行审查提示词/量规（含反 AI 味词表引用与 hook/payoff 子项）；
- **评估器**：L0 标注集上，候选量规的审查结论与人类判决的一致率；
- **配置**：50-100 代、便宜模型为主、级联评估（先跑规则项再跑 LLM 审查）、预算上限 $20；
- **预期产出**：量规 v2 + 一致率提升报告 + 刷分检测（留出集对照）。一致率从基线提升 5 个百分点即判定路线成立，再扩展到技法卡。

## 七、路线图

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M0 评估加固 | 标注集 + 各自动信号一致率基线 | 至少 2 个信号 ≥ 0.8 可入适应度 |
| M1 量规进化 PoC | OpenEvolve sidecar，离线沙盒 | 留出集一致率 +5pp，无刷分迹象 |
| M2 技法卡进化 | 沙盒回放复合适应度 | 影子模式 30 章对照胜出 |
| M3 内生进化 | `pensoul-evolve` crate 产品化 | 人工门晋升 1 次全流程走通，可回滚 |

## 八、红线（继承 agent.md 并追加）

1. 不进化章节正文、不进化安全规则、不进化门控语义；
2. 进化沙盒与密钥隔离，标注集不含用户私密正文出 `data/`；
3. 任何晋升必须人工确认，进化系统无自动写正典数据权限；
4. 每轮进化预算双熔断，超支即停。
