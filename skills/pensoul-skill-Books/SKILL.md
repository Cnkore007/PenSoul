# PenSoul · 书籍写作蒸馏术

> 蒸馏的不是这本书讲了什么，而是这本书怎么写。
> 让一部作品的写作方法，变成你工作流里可拆可装的技能卡。

## 核心理念

本技能做的是**提炼写法**，不是提炼内容。

一张好的写作技能卡是一套可以被工作流直接执行的方法：
- 这本书如何**遣词造句**？（文风 DNA）
- 如何**布局谋篇**？（叙事结构）
- 如何**让人物立起来**？（人物塑造）
- 如何**让读者停不下来**？（冲突与张力）
- 如何**驾驭题材惯例**？（类型范式）

**关键区分**：捕捉的是 HOW it is written，不是 WHAT it says，更不是内容梗概。

**产物红线**：技能卡中**不保留内容梗概**——不写情节摘要、不抄书摘段落、不做读后感。引用书中位置只为定位技法证据，产出的卡只保留可执行的写作方法。

## 约定

- `<cards_root>`：产物根目录，默认为项目一级目录 `WritingCard/`（供工作流页面直接绑定）。一次蒸馏产出一个技能包 `<cards_root>/<书名>-book/`，内含 1-5 张维度卡。
- 五个维度（slug / 中文名 / 适用工作流环节）：

| slug | 维度 | 提取重点 | 适用环节 |
|------|------|---------|---------|
| `style` | 文风 DNA | 句式、词汇、节奏、视角声音、叙事距离 | 章节写作、一致性审查 |
| `structure` | 叙事结构 | 篇章布局、信息揭示顺序、伏笔与回收、视角调度 | 细纲展开 |
| `character` | 人物塑造 | 角色登场、动机呈现、成长弧线、群像调度 | 细纲展开、章节写作 |
| `tension` | 冲突与张力 | 悬念引擎、张力曲线、场景冲突设计、章末钩子 | 细纲展开、章节写作 |
| `genre` | 类型范式 | 题材惯例、读者期待管理、范式突破点 | 细纲展开 |

- 应用内蒸馏由后端命令按本手册分阶段执行，每阶段进度实时推送给前端。

## 输入模式

| 模式 | 触发条件 | 策略 |
|------|---------|------|
| **知识蒸馏**（默认） | 仅提供书名 + 作者 | 基于模型的作品知识蒸馏，不确定处标注置信度，诚实边界中声明「非逐字文本核对」 |
| **样章增强** | 用户附加样章文本 | 样章为一手素材（权重最高），作品知识补充全景与跨章证据 |

冷门作品（模型知识储备不足）必须在阶段 0 就声明，降低卡数与置信度，禁止强行编造。

## 执行流程

### 阶段 0：整书理解（1 次 LLM 调用）

产出 `OVERVIEW.md`，四个部分：

1. **写法骨架**：这本书在写作方法上最值得学的 3-5 个支柱（每个一句话点破）
2. **写法光谱**：句法长短、视角选择、叙事距离、信息控制、节奏取向的总体定位
3. **批判**：什么不该学——时代局限、类型局限、作者已知的写作短板
4. **维度预判**：每个勾选维度的一句话方向预判（阶段 1 的提取靶子）

### 阶段 1：维度提取 + 三重验证（1 次 LLM 调用）

对每个勾选维度提取 3-5 个候选技法。每个候选必须通过三重验证：

- **V1 跨章复现**：书中至少 2 个独立位置有体现（不是孤例）
- **V2 生成力**：能用它指导一个书里没写过的新场景（不是死描述）
- **V3 独特性**：不是所有作者都会这样做的常识（不是正确的废话）

三重全过 → 正式技法；过 1-2 重 → 降级为附注；0 重 → 丢弃。
验证结论随候选一并输出，保留审计轨迹。

### 阶段 2：逐维构卡（每维度 1 次 LLM 调用）

每张卡按 RIA++ 六段构造（写作版）：

| 段 | 内容 | 要求 |
|----|------|------|
| **R 手法出处** | 体现该技法的典型位置 | 章/场景级定位；知识蒸馏模式标「凭作品整体印象」 |
| **I 技法骨架** | 用自己的话重写方法核心 | 5-15 行，没读过原书的人能看懂在做什么 |
| **A1 书中案例** | 作者用这招解决了什么写作问题 | 1-3 个：遇到什么问题 → 怎么用 → 效果是什么 |
| **A2 适用场景** ★ | 什么时候该绑这张卡 | 3-5 个可识别场景 + 何时不绑；这是工作流绑卡的决策依据 |
| **E 执行步骤** | 写作时的 1-2-3 步骤 | 每步有可判断的完成标准；「保持克制」不是步骤，「本章第一个冲突点落在 300 字以内」才是 |
| **B 边界** | 何时失效 | 什么题材/章节不该用 + 作者已知盲点 + 知识蒸馏模式的置信度声明 |

卡片 frontmatter：

```yaml
---
name: <书名>-book-<维度slug>     # 与目录结构一致，禁止改动
description: <何时绑这张卡 + 何时不绑，≤200 字，面向工作流绑卡决策>
source_book: 《书名》作者
dimension: <维度slug>
applicable_stages: [<适用环节>]  # outline_expand / chapter_writing / review
---
```

### 阶段 3：交付

```
<cards_root>/<书名>-book/
├── package.json             # 包元数据（书名/作者/蒸馏时间/维度清单）
├── OVERVIEW.md              # 阶段 0 产出
├── INDEX.md                 # 技能包索引（书目 + 各卡一句话 + 维度覆盖）
├── <维度slug>/SKILL.md      # 每张维度卡
└── references/research/     # 阶段 0/1 原始产出存档（自包含）
```

INDEX.md 由程序生成，不占用 LLM 调用。

## 质量红线（违反则该卡重写）

1. 每张卡必须通过全部三重验证
2. 六段齐全，E 段必须是可执行动作而非态度口号
3. 禁止内容梗概进卡——蒸馏写法，不是抄情节
4. 知识蒸馏模式必须在 B 段标注「基于模型知识储备，非逐字文本核对」
5. 单卡正文控制在 6000 字以内——卡是工作手册，不是论文
6. 宁可产 2 张过硬的卡，不产 5 张注水的卡；某维度提取全部未过验证时，该维度不产卡

## 与 pensoul-skill-Experts 的生态分工

- **pensoul-skill-Experts**：蒸馏人（思维方式），参与**灵魂萌芽的讨论**（评审视角）
- **pensoul-skill-Books**（本技能）：蒸馏书（写作方法），绑定**工作流的执行环节**（动笔干活）

讨论定方向，技能管落地。两者都进对应页面直接使用，互不越界。

## 最后

一本书的真正遗产，不是它讲过的故事，而是它讲故事的方式。

好的技能卡让作者不必读完三百万字，也能把那三百万字里练出的手艺，装进自己的下一章。
