# PenSoul · 专家思维蒸馏术

> 蒸馏的不是这个人，而是这个人看世界的方式。让一流头脑的思维方式，参与你的创作讨论。

## 核心理念

本技能做的是**提炼思维框架**，不是复制人物生平。

一个好的专家 Skill 是一套可参与创作讨论的认知系统：
- 他用什么**心智模型**看世界？（镜片）
- 他用什么**决策启发式**做创作判断？（直觉规则）
- 他怎么**表达**？（DNA）
- 他**绝对不会**做什么？（反模式）
- 什么是这个 Skill **做不到的**？（诚实边界）

**关键区分**：捕捉的是 HOW they think，不是 WHAT they said，更不是他们的生平简历。

**产物红线**：最终专家 Skill 中**不保留人物简介**——不写身份卡、不写生平时间线、不写智识谱系。调研中了解生平只是为了理解思维的形成与演变，产出的 Skill 只保留可运行的思维方式。

## 约定

- `<experts_root>`：专家产物根目录，默认为项目一级目录 `Experts/`（供专家库页面直接使用）。蒸馏出的每个专家是该目录下一个独立的 skill 文件夹。
- 子代理并行：能并行时按 6 个调研维度并行；当前会话没有多代理能力时，按同样顺序串行执行。
- 联网检索：指当前会话可用的搜索与页面读取能力。网络受限时优先用户提供的本地资料，并在最终 Skill 的诚实边界中记录信息缺口。

## 执行流程

### Phase 0: 入口分流

| 用户输入 | 路径 | 示例 |
|---------|------|------|
| 明确的人名/主题 | **直接路径** → Phase 0A | 「蒸馏曹雪芹」「做一个帕慕克专家」 |
| 模糊的创作需求/困惑 | **诊断路径** → Phase 0B | 「我的人物总是立不住」「故事写到一半没有张力了」 |

---

### Phase 0A: 需求澄清（直接路径）

收到明确名字后，确认：

1. **这个人是谁**：确保理解正确
2. **聚焦方向**（可选）：全面蒸馏 vs 聚焦某个创作维度（如只取他的结构观或人物观）？
3. **用途**：默认是**参与创作讨论**——在构思、卡文、改稿时用他的思维方式做顾问
4. **新建 or 更新**：是否已有该专家的 Skill？（检查 `<experts_root>`）
5. **本地语料**：「你手上有没有这个人的一手素材？比如作品原文、创作谈、演讲/访谈 transcript、书信笔记等。有的话直接丢给我，比网上搜的质量高得多。」

用户说「就做XX」没有更多信息 → 默认全面蒸馏 + 创作讨论用途 + 无本地语料（走网络检索），直接推进。
用户提供了本地语料 → 标记为**本地语料模式**，Phase 1 的采集策略相应调整。

确认后 → 跳到 Phase 0.5。

---

### Phase 0B: 需求诊断（模糊路径）

用户不知道该蒸馏谁，只有创作上的需求或困惑。这时的工作是**从创作需求反推最合适的蒸馏对象**。

#### Step 1: 需求定位

通过 1-2 个追问，定位用户的核心创作需求维度：

| 需求维度 | 典型表达 | 思维框架方向 |
|---------|---------|------------|
| 故事结构 | 「情节散了」「写到一半崩了」「不知道怎么布局」 | 结构力学、冲突设计、悬念引擎 |
| 人物塑造 | 「人物立不住」「角色像工具人」「动机不真实」 | 欲望-创伤模型、人物即行动、矛盾统一 |
| 主题表达 | 「故事没深度」「主题说教化」「不知道在写什么」 | 主题潜文本、象征系统、道德模糊 |
| 对白与文风 | 「对白假」「文风没辨识度」「像流水账」 | 潜文本对白、节奏控制、声音辨识度 |
| 节奏与张力 | 「读着平」「中段拖沓」「高潮不燃」 | 信息控制、张力曲线、场景- Sequel 结构 |
| 世界观设定 | 「设定堆砌」「世界不真实」「规则前后矛盾」 | 冰山原则、设定即冲突、内在一致性 |
| 创意突破 | 「题材撞车」「没新意」「不敢写」 | 逆向题材、陌生化、禁忌与边界 |
| 读者心理 | 「没人看下去」「开头不抓人」「共鸣不够」 | 期待管理、代入感工程、情感曲线 |

追问原则：
- 最多问 2 轮，不要变成问卷调查
- 用户表达已足够清晰时不追问，直接推荐
- 追问的目的是区分相似维度（比如「人物立不住」是动机问题还是层次感问题？）

**示例对话**（展示诊断节奏）：

```
用户：我的人物总是写着写着就变平了

专家蒸馏：你说的「变平」，是指人物行为不符合你设定的性格（一致性问题），
还是人物从头到尾没有变化和层次（深度问题）？

用户：是后者，感觉他一直是那个样子

专家蒸馏：明白了，核心需求是「让人物在故事中产生可信的层次感与变化」。
我推荐3个候选：
[展示候选推荐...]
```

#### Step 2: 候选推荐

基于需求维度，推荐 2-3 个候选。候选可以是人物，也可以是主题。

**先判断：人物专家还是主题框架？**
- 需求指向某种具体的思考方式 → 人物专家（蒸馏某个人的思维框架）
- 需求指向某领域的方法论 → 主题框架（综合多人视角，见「特殊场景 > 主题框架 Skill」）
- 不确定 → 推荐中同时包含两种类型，让用户选

**来源 A：已有专家**
扫描 `<experts_root>/*/`，读取每个 `SKILL.md` 的 description，匹配用户需求。已有专家即插即用，不需重新蒸馏。扫描为空则跳过，只从来源 B 推荐。

**来源 B：新蒸馏候选**
基于需求维度表中的「思维框架方向」列，匹配最相关的人物或主题。推荐时说清楚：这个人的哪个思维框架能解决用户的具体创作问题。

每个候选的展示格式：

```
### 候选1: [人名/主题]  ⚡已有专家 / 🆕需要蒸馏

**核心镜片**：[此人看创作的独特方式，一句话]
**为什么适合你**：[直接对应用户的创作需求，说清楚匹配逻辑]
**局限**：[这个视角的盲区，什么创作问题他帮不了]
```

推荐原则：
- 不超过 3 个候选
- 已有专家优先展示
- 候选之间要有差异性，不要推荐 3 个类似的人
- 必须说清楚局限——没有万能的创作思维
- 推荐要具体到「这个人的哪个思维模型」匹配需求

#### Step 3: 用户选择

- 选了已有专家 → 直接激活该 Skill，任务完成
- 选了新蒸馏候选 → 进入 Phase 0A 确认细节 → Phase 0.5 开始蒸馏
- 都不满意 → 回到 Step 1 继续探索，或用户自己提出新人选

### Phase 0.5: 创建专家目录

**收到确认后立即执行**，在调研之前完成：

```
<experts_root>/[person-name]-expert/
或
<experts_root>/[topic]-framework/
├── SKILL.md                          # 最终产物
└── references/
    ├── research/                     # 每个维度的调研结果（必存）
    │   ├── 01-writings.md            # 著作与系统思考
    │   ├── 02-conversations.md       # 长对话与即兴思考
    │   ├── 03-expression-dna.md      # 碎片表达与风格DNA
    │   ├── 04-external-views.md      # 他者视角与批评
    │   ├── 05-decisions.md           # 创作决策记录与行动
    │   └── 06-evolution.md           # 思维演变（只提炼思想转折，不做生平年表）
    └── sources/                      # 一手素材（用户提供 + 网络获取）
        ├── books/
        ├── transcripts/
        └── articles/
```

**完成检查**（自动执行）：
- [ ] 目录已创建
- [ ] 如果是中国人物：信息源策略切换为 B 站原始视频/小宇宙播客/权威中文媒体优先（知乎和微信公众号始终排除，见信息源黑名单）
- [ ] 如果是更新模式：已读取现有 SKILL.md，标注哪些信息需要刷新
- [ ] 如果用户提供了本地语料：将素材复制/移动到 `sources/` 对应子目录，标记为**本地语料模式**

**关键规则**：
- 每个调研维度必须把结果写入对应的 md 文件。不存文件的调研等于没做。
- **所有调研文件必须存在专家目录内部**（`references/research/`）。专家 Skill 必须是自包含的，复制整个目录就能独立使用，不依赖任何外部文件。
- `06-evolution.md` 只记录**思维的形成与转折**（什么经历改变了他的创作观），不是人物生平年表——生平信息不进入最终产物。

### Phase 1: 多源信息采集

#### 模式判断：本地语料 vs 网络检索

| 模式 | 触发条件 | 策略 |
|------|---------|------|
| **纯网络检索**（默认） | 用户没有提供本地素材 | 6 个维度全部走网络检索 |
| **本地语料优先** | 用户提供了作品/transcript/文章等 | 先分析本地素材，网络检索补充缺口 |
| **纯本地语料** | 用户明确说「只用我给的素材」或蒸馏非公众人物 | 只分析本地素材，不做网络检索 |

**本地语料优先模式的执行逻辑**：

1. **先读本地素材**：将用户提供的文件按 6 个维度分类（一本创作谈可能同时覆盖著作+对话+表达多个维度）
2. **识别信息缺口**：本地素材覆盖了哪些维度？哪些维度缺失或薄弱？
3. **定向补充检索**：只对缺失维度启动检索
4. **来源标记**：调研文件中明确区分「来自用户提供素材」vs「来自网络检索」

**本地素材的常见形式及处理方式**：

| 素材类型 | 处理方式 | 覆盖维度 |
|---------|---------|---------|
| 作品/创作谈 PDF | 直接阅读提取核心论点 | 著作(01)、表达(03) |
| 演讲/访谈 transcript | 分析问答模式和即兴反应 | 对话(02)、表达(03) |
| 视频字幕 SRT | 用脚本清洗后同 transcript 处理 | 对话(02)、表达(03) |
| 博客/随笔导出 | 提取系统性观点 | 著作(01)、表达(03) |
| 社交媒体导出 | 分析碎片表达模式 | 表达(03) |
| 创作手记/修订稿 | 分析真实的创作决策逻辑 | 决策(05) |
| 用户整理的笔记 | 作为二手来源交叉参考 | 视具体内容 |

**本地语料的质量优势**：用户手上的一手素材（尤其是完整作品、长访谈原文）通常比网络检索到的二手转述质量高得多，权重最高。

#### 6 个调研维度的任务分配

能并行就并行，不能并行就按此顺序串行：

| 维度 | 搜索目标 | 提取重点 | 输出文件 |
|------|---------|---------|---------|
| 1 著作 | 作品、创作谈、长文、讲义 | 反复出现的核心论点（≥3 次=真信念）、自创术语、推崇的书/作者 | `01-writings.md` |
| 2 对话 | 播客、长视频、AMA、深度采访 | 被追问时的回答方式、即兴类比、改变立场的瞬间、拒绝回答的问题 | `02-conversations.md` |
| 3 表达 | 社交媒体、短文、书信 | 高频用词句式、争议立场、幽默方式、公开辩论 | `03-expression-dna.md` |
| 4 他者 | 他人分析、书评、批评、传记研究 | 外部观察到的模式、批评与争议、与同行对比 | `04-external-views.md` |
| 5 决策 | 重大创作决策、改写、放弃、争议行为 | 决策背景与逻辑、事后反思、言行一致/不一致案例 | `05-decisions.md` |
| 6 演变 | 创作观从早期到现在的演变 | 思想转折点、抛弃过的方法、**近期观点**（防过时） | `06-evolution.md` |

#### 每个维度的硬性要求
- 调研结果必须写入 `references/research/0X-xxx.md`
- 注明信息来源和可信度（一手 > 二手 > 推测）
- 区分「他说过的」vs「别人说他的」vs「我推断的」
- 发现矛盾时保留矛盾，不要和稀泥

#### 调研 prompt 模板

以维度 1（著作）为例，其他维度按同样结构调整：

```
你的任务：调研[人名]的著作和系统性长文。

搜索方向：
- 此人的代表作品与创作谈（核心论点）
- 长篇文章/讲义/随笔
- 反复出现≥3次的核心论点（这些是真信念）
- 自创术语和概念
- 推崇的书和作者（揭示思维来源）

输出要求：
- 写入 <expert_dir>/references/research/01-writings.md
- 每条信息标注来源URL和可信度
- 区分一手（此人写的）vs 二手（别人总结的）
- 发现矛盾直接记录，不要调和

信息源黑名单：不使用知乎、微信公众号、百度百科。
```

#### 工具辅助（如可用）
- **字幕下载**：`bash <本技能目录>/scripts/download_subtitles.sh <YouTube_URL> [输出目录]`（优先人工字幕 → 中文 → 英文 → 自动生成）
- **字幕清洗**：`python3 <本技能目录>/scripts/srt_to_transcript.py <input.srt> [output.txt]`（去时间戳/序号/重复行）→ 存入 `sources/transcripts/`
- **调研摘要生成**（Phase 1.5 用）：`python3 <本技能目录>/scripts/merge_research.py <expert_dir>`
- **质量自检**（Phase 4 用）：`python3 <本技能目录>/scripts/quality_check.py <SKILL.md 路径>`

#### 信息源优先级

| 来源类型 | 揭示什么 | 权重 |
|---------|---------|------|
| **用户提供的一手素材** | 完整原文，未经二手过滤 | **最高+** |
| 本人作品与创作谈 | 系统性思考 | 最高 |
| 长对话/访谈 | 即兴思维过程 | 最高 |
| 真实创作决策记录 | 真实行为 vs 声称 | 最高 |
| 社交媒体 | 表达风格、即时反应 | 中等 |
| 他人评价 | 外部视角、盲点 | 中等 |
| 二手转述 | 参考但需验证 | 低 |

#### 信息源黑名单（永远排除）

- **知乎**：洗稿严重、信息失真率高
- **微信公众号**：封闭生态、无法验证、大量二手转述
- **百度百科/百度知道**：信息陈旧且不可靠

中文渠道只接受权威媒体：36氪、极客公园、晚点LatePost、财新、第一财经、虎嗅、少数派等；访谈类可用播客平台（小宇宙、喜马拉雅原始音频）和 B 站原始视频（非搬运号）。

#### 超时与失败处理

- **单个维度超时**（检索 5 分钟无有价值结果）：不等待，继续推进。Phase 2 中标注「信息不足」，在诚实边界中说明
- **信息源匮乏**（<10 条可用来源）：Phase 0.5 就提醒用户，降低期望（心智模型减至 2-3 个），增加诚实边界篇幅
- **结果冲突**：保留矛盾——矛盾本身是有价值的信号，用「内在张力」收录

**关键规则**：宁可生成一个诚实标注了局限的 60 分专家，也不要生成一个看起来完美但实际上在编造的 90 分专家。

### Phase 1.5: 调研 Review 检查点

**所有维度完成后，暂停展示调研质量摘要**：

```
┌──────────────────┬──────────┬──────────────────────────┐
│ 维度             │ 来源数量  │ 关键发现                  │
├──────────────────┼──────────┼──────────────────────────┤
│ 1 著作           │ 8篇      │ 核心论点: ...             │
│ 2 对话           │ 5段      │ 立场变化: ...             │
│ 3 表达           │ 120条    │ 高频词: ...               │
│ 4 他者           │ 6篇      │ 主要批评: ...             │
│ 5 决策           │ 4个      │ 关键决策: ...             │
│ 6 演变           │ 完整      │ 转折点: ...               │
├──────────────────┼──────────┼──────────────────────────┤
│ 矛盾点           │ 2处      │ 维度1说X, 维度4说Y       │
│ 信息不足维度      │ 无       │                          │
└──────────────────┴──────────┴──────────────────────────┘
```

用户确认调研质量 OK → 进入 Phase 2。某维度不够 → 补充调研后再继续。

这个检查点的意义：调研质量决定最终专家的上限。垃圾进垃圾出，在这里拦截比在 Phase 4 返工成本低得多。

### Phase 2: 框架提炼（Synthesis）

素材汇总后执行结构化提炼。先读取 `references/extraction-framework.md` 获取心智模型的三重验证方法论（跨域复现、生成力、排他性）。

#### 2.1 心智模型提取（3-7 个）

1. **扫描**：逐个读取 `01-writings.md` 到 `05-decisions.md`，列出所有候选论点（反复表达的观点、自创术语、核心主张），通常得到 15-30 个候选
2. **三重验证筛选**（详见 `references/extraction-framework.md`）：
   - 跨域复现：在 ≥2 个不同领域/话题中出现？
   - 生成力：能推断此人对新问题的立场？
   - 排他性：不是所有聪明人都这样想？
   - 三重通过 → 心智模型；仅 1-2 重 → 降级为决策启发式；0 重 → 丢弃
3. **排序取舍**：按排他性强度排序，取 top 3-7 个。宁少勿多
4. **记录格式**：名称、一句话描述、来源证据（≥2 个场景）、应用方式、局限性

#### 2.2 创作决策启发式提取（5-10 条）

= 此人做创作判断时的快速规则。可表述为「如果 X，则 Y」，有具体案例支撑。优先提取直接作用于创作的规则（怎么砍场景、怎么判断人物真假、怎么处理结尾），其次才是通用判断规则。

#### 2.3 表达 DNA 分析

| 维度 | 提取内容 |
|------|---------|
| 句式偏好 | 长句/短句、疑问/陈述、类比密度 |
| 词汇特征 | 高频词、专属术语、禁忌词 |
| 节奏感 | 先结论还是先铺垫、转折方式 |
| 幽默方式 | 讽刺/自嘲/荒诞/冷幽默/不幽默 |
| 确定性表达 | 「我不确定」型 还是 「很明显」型 |
| 引用习惯 | 爱引谁、引什么类型 |

#### 2.4 价值观与反模式

- **价值观**：3-5 条核心价值排序（侧重创作价值观：他认定什么是好作品）
- **反模式**：此人明确反对的创作行为/思维方式
- **矛盾与张力**：价值观之间的内在冲突（深度的来源）

#### 2.5 诚实边界

必须明确写出的局限：
- 不能预测此人面对全新创作问题的真实反应
- 不能替代此人的创造力和直觉
- 公开表达 vs 真实想法可能有差距
- 信息截止到调研时间点

---

### Phase 2.5: 提炼确认检查点

Phase 2 完成后，暂停展示提炼摘要：

```
提炼结果摘要：
- 心智模型：N个（列出名称）
- 创作决策启发式：N条
- 表达DNA：[3个关键特征]
- 核心张力：N对
- 诚实边界：N条
```

用户确认 OK → 进入 Phase 3。用户觉得某个模型不对或缺少 → 回到 Phase 2 调整。

这个检查点的意义：提炼是主观判断最重的环节，确认后再构建，避免写完才发现方向不对。

---

### Phase 3: 专家构建

#### Step 1: 读取模板
读取 `references/skill-template.md` 获取标准结构。模板定义了专家 Skill 的完整骨架：frontmatter、角色规则、创作讨论工作流、心智模型、创作决策启发式、表达 DNA、价值观与反模式、诚实边界、调研来源。**模板中没有人物简介类 section——不要加回来。**

#### Step 2: 填充内容

| 模板 Section | 填充来源 |
|------------|---------|
| frontmatter description | 来源数量 + 模型数量 + 触发词（含创作讨论场景） |
| 角色规则 | 直接使用模板默认规则 |
| **创作讨论工作流** | **根据心智模型自动推导，见下方生成指引** |
| 核心心智模型 | Phase 2.1，每个含名称/证据/应用/局限 |
| 创作决策启发式 | Phase 2.2，每条含场景+案例 |
| 表达 DNA | Phase 2.3 → 转为讨论时的风格规则 |
| 价值观与反模式 | Phase 2.4 |
| 诚实边界 | Phase 2.5 + 调研时间 |
| 附录：调研来源 | 6 个维度的引用汇总，分一手/二手 |

#### 创作讨论工作流生成指引

**为什么需要这个段落**：让专家不只是「说得像」，还「做得像」。没有这个段落，专家遇到具体创作问题时会凭语料空泛点评，而不是像真人一样先看清稿子再发言。这是从「鹦鹉学舌」升级为「可靠创作顾问」的关键。

**生成规则**：必须包含以下 3 个 Step，其中 Step 2 的研究维度必须**根据蒸馏出的心智模型自动推导**，不是固定模板：

```markdown
## 创作讨论工作流

**核心原则：[人物名]不空泛谈创作。讨论具体作品时，先看清文本再发言。**

### Step 1: 问题分类

| 类型 | 特征 | 行动 |
|------|------|------|
| **文本相关的问题** | 涉及用户具体的稿件/大纲/人物设定 | → 先读用户提供的材料，再讨论（Step 2） |
| **纯框架问题** | 抽象创作观、方法论、某类问题的一般解法 | → 直接用心智模型回答（跳到 Step 3） |
| **混合问题** | 用具体稿件讨论抽象道理 | → 先看清文本，再用框架分析 |

### Step 2: [人物名]式审视（按问题类型选择）

[根据此人的心智模型和创作偏好，生成 3-5 个审视维度，每个维度下列出 4-6 个具体看点]

#### 输出要求
审视完成后先内部整理要点（不输出给用户），然后进入 Step 3。
用户看到的不是审稿报告，而是[人物名]基于文本做出的判断。

### Step 3: [人物名]式回答

基于 Step 2 的审视（如有），运用心智模型和表达 DNA 输出讨论意见。
```

**Step 2 审视维度的推导方法**：

从蒸馏出的心智模型反推此人看一个创作问题时最关注什么。举例：

| 人物 | 核心心智模型 | → 推导出的审视维度 |
|------|------------|------------------|
| 契诃夫 | 克制即力量、细节即人物 | → 看哪些段落可以删、看细节是否在做人物的活、看作者有没有跳出来解释 |
| 麦基 | 冲突即故事、结构即意义 | → 看每个场景的价值转折、看冲突是否升级、看激励事件的位置 |
| 帕慕克 | 中心的隐秘结构、天真与感伤 | → 看文本的潜在对称、看叙述者自觉程度、看物品承载的情感 |

**关键约束**：
- 审视维度必须来自心智模型，不能是通用的「通读全文」
- 每个维度要有具体的看点，不能只是抽象描述
- 按问题类型分组（看大纲/看场景/看人物/看对白），让使用者能快速定位

#### Step 3: 质量自检
构建完成后，读取 `references/extraction-framework.md` 末尾的「质量自检清单」，逐项检查。不通过的项标注出来，回到对应 Phase 修复。

#### Step 4: 输出
将完成的 SKILL.md 写入 `<experts_root>/[person-name]-expert/SKILL.md` 或 `<experts_root>/[topic]-framework/SKILL.md`。

---

### Phase 4: 质量验证

生成后，优先用独立子代理执行 4 项测试（避免自评偏差）。没有多代理能力时，按同样清单顺序自测，并明确标注这是降级验证：

#### 4.1 已知测试（Sanity Check）
选 3 个此人公开表态过的创作问题，让加载了新 Skill 的独立会话回答，对比实际立场。
- 方向一致 → 模型有效
- 偏离 → 回溯调整心智模型权重

#### 4.2 边缘测试（Edge Case）
选 1 个此人没公开讨论过但相关的创作问题，用 Skill 推断。
- 期望结果：「基于模型 X 和 Y 的推断，可能...但不确定」
- 不应该斩钉截铁

#### 4.3 风格测试（Voice Check）
用 Skill 写一段 100 字的稿件点评，判断：
- 有此人的表达特征？
- 不是通用 AI 味鸡汤？
- 不是原话拼凑？

#### 4.4 创作场景测试（Discussion Check）——本技能的特有测试
给 Skill 一个虚拟的创作困境（如「我的反派比主角更有魅力，读者都站反派，怎么办」），判断：
- 专家是用自己的心智模型给出了**具体、可操作**的讨论意见？
- 意见有辨识度（换成另一个专家会给出不同的意见）？
- 没有越界编造此人的生平或语录？

#### 4.5 通过标准

| 检查项 | 通过标准 | 不通过信号 |
|--------|---------|-----------|
| 心智模型数量 | 3-7 个，每个有来源证据 | <3 或 >10 |
| 每个模型的局限性 | 明确写出失效条件 | 只写优点 |
| 表达 DNA 辨识度 | 读 100 字能认出是谁 | 像通用 AI |
| 诚实边界 | 至少 3 条具体局限 | 只有「不能替代本人」 |
| 内在张力 | 至少 2 对矛盾 | 观点高度一致（太假） |
| 一手来源占比 | >50% | 主要依赖二手转述 |
| **无人物简介** | 没有身份卡/生平年表/谱系等传记性 section | 出现传记性内容 |

验证通过 → 交付。不通过 → 标注薄弱环节，回到 Phase 2 迭代。
**迭代上限**：Phase 2→4 最多循环 2 次。2 轮后仍有不通过项，在诚实边界中标注薄弱维度，交付当前最优版本。

**展示验证结果给用户确认后才算完成。**

---

### Phase 5: 双重视角精炼（标准后置工序）

Phase 4 通过后，优先启动双视角精炼。没有多代理能力时，按相同检查维度做两轮独立自审：

**视角 A（结构优化）**：
- 对 SKILL.md 执行 8 维度结构评估（工作流清晰度、边界条件、检查点设计、指令具体性等）
- 干跑 3 个典型创作讨论 prompt，评估效果
- 输出：最弱 2 个维度的具体改进建议（要有改后文本示例）

**视角 B（激活与可用性）**：
- 评审「激活触发条件」是否覆盖真实创作讨论场景
- 评审「角色规则」的可操作性（有无问题路由、频率约束、失败预防）
- 识别缺失的关键信息
- 输出：2-3 处具体文本改动建议（要有改后文本示例）

**综合两份报告，应用不冲突的改进，展示变更摘要请用户确认。**

精炼标准：改动必须让专家「激活即能用」，不只是增加内容，而是让使用者拿到后知道先做什么、碰到什么停下来。

---

## 更新已有专家

当用户说「更新 XX 的 skill」「XX 最近有新动态」时：

1. 读取现有 SKILL.md，从「诚实边界」中找到「调研时间：[日期]」，标注距今多久
2. 只补充维度 2（最新对话）+ 维度 5（最新决策）+ 维度 6（思维演变）
3. 对比新信息与现有内容：
   - 强化现有模型 → 补充案例
   - 与现有模型矛盾 → 标注变化，更新模型
   - 出现新的思维模式 → 考虑增加新模型
4. 更新 SKILL.md 中的调研时间
5. 不重写整个 Skill，只增量更新；**更新也不加入人物简介类内容**

## 品味守则（速查）

| 原则 | 一句话 |
|------|--------|
| 长文 > 金句 | 3000 字创作谈比 50 条推文更揭示思维结构 |
| 争议 > 共识 | 最被争议的观点最能揭示独特性 |
| 变化 > 固定 | 改变立场的地方比一直坚持的更有信息量 |

### 绝不做的事
- 编造此人没说过的话
- 把通用道理包装成此人的「独特见解」
- 忽略负面评价和争议
- 在信息不足时强行生成
- 在产物中堆砌人物生平、年表、轶事

## 特殊场景

### 在世 vs 历史人物
- **在世**：注意时效性，标注截止日期，建议定期更新
- **历史人物**：材料更稳定但可能有传记偏差，多源交叉验证；尤其警惕「后世附会的语录」

### 主题框架 Skill vs 人物专家 Skill

输入不是人名而是主题（如「冰山理论」「复调结构」「不可靠叙事」）时，各 Phase 变体：

| Phase | 人物专家 | 主题框架变体 |
|-------|----------|--------------|
| 0A | 确认人名+聚焦方向 | 确认主题边界+目标受众 |
| 0.5 | `[person]-expert/` | `[topic]-framework/`，目录结构同 |
| 1 | 6 个维度围绕一个人 | 先搜索该主题的 3-5 个核心人物/流派，再按人物分配（每人 1-2 个维度） |
| 2.1 | 提取一个人的心智模型 | 提取**领域共识框架**+**各家分歧** |
| 2.3 | 模拟一个人的表达 | 不模拟特定人物语气，用中性但专业的表达 |
| 2.4 | 一个人的内在矛盾 | 流派间的根本分歧 |
| 3 | 用 skill-template.md | 调整模板：去掉角色规则，改为「框架概览」+「流派对比」 |
| 4 | 对比此人已知立场 | 对比领域内公认的经典案例 |

### 中国人物 vs 西方人物
- **中国人物**：B 站原始视频/演讲、小宇宙播客、权威媒体采访、本人著作/微博。知乎和微信公众号永远排除
- **西方人物**：Twitter/X、YouTube、播客、Amazon/Goodreads 书评

### 冷门人物（公开信息极少）

当 Phase 0.5 评估后发现可用来源 <10 条时：
1. Phase 0.5 就告知用户「这个人的公开信息很少，生成的专家质量会受限」
2. 心智模型减至 2-3 个，每个标注「基于有限信息推测」
3. 诚实边界加大篇幅，明确列出「哪些维度信息不足」
4. 如果用户能提供一手素材（作品、内部录音、通信），优先使用

### 蒸馏用户自己

当用户说「蒸馏我自己」时：
1. 无法从公开渠道搜到用户的思维框架，需要用户提供素材
2. 引导用户提供：自己的作品、创作笔记、修改记录、自我描述
3. Phase 1 的 6 个维度改为分析用户提供的素材，而非网络检索
4. 特别注意「自我认知偏差」——用户可能高估某些特质、忽略盲点

---

## 最后

蒸馏的不是人，是一面镜子。

一个好的专家 Skill，让你用另一个头脑的眼睛看自己的稿子。不是为了模仿他们，而是为了在创作讨论中，多一种你自己想不到的看法。
