# PenSoul — AI 长篇小说创作平台

让引擎管流程，让模型管创作。

PenSoul 是一个面向网络文学作者和严肃小说创作者的 AI 写作工具，基于 Rust + Tauri 构建，解决 500 万字级别超长篇小说的一致性、长期记忆和协同编辑问题。

## 核心理念

主流 AI 写作工具把流程写在提示词里，建议 AI 按步骤来——但建议终究只是建议，AI 会跳步、会绕过一致性检查、会忘记伏笔。PenSoul 换了一条路：

| 维度 | 主流做法 | PenSoul |
|------|---------|---------|
| 流程控制 | 写在提示词里（建议） | 写在引擎的确定性逻辑里（约束） |
| AI 行为 | AI 自觉遵守，可跳步 | 引擎硬性驱动，不可绕过 |
| 质量保障 | 可选步骤 | 必经之路（门控放行） |
| 工作流 | 写死在代码里 | P0 硬编码编排，P1 声明式工作流模板 |

## 核心功能

- **Harness 引擎** — 确定性流程引擎，用 Stage/Gate/WAL 驱动创作流程，支持自动/人工/条件三种门控模式与崩溃恢复
- **工作流模板化** — 作品库全局模板库 + 项目引用分层；模板可增删执行环节（含章前策划），环节绑定模型与写作技法卡
- **章节连写管线** — 章前策划 → 写作 → 审查（异模型门控）→ 回灌自动连写，支持暂停/继续/停止；黄金三章硬门控（钩子/爽点子分数必达标）
- **四层记忆系统** — 热/温/冷/叙事四级记忆，8 步更新管道，预算按编辑模式分配（默认 8000 token）
- **CDA 一致性驱动架构** — 基于影响图的 BFS 传播，千章规模构建 < 50ms，修改后自动标记受影响章节
- **多 Agent 讨论** — 立论/交锋两轮交锋后成果按维度并行提炼，跨维度冲突显式标记，未收敛分歧由独立裁判逐条裁决；生成前需作者确认或填写补充意见，可一键重新讨论
- **全链路批注** — 笔耕行内/整章批注之外，细纲、脉络节点、人物志、世界观各实体均可批注；侧边栏「批注中心」聚合全部待处理批注，可跨页跳转、就地采纳/拒绝
- **受控保存（保存并审核）** — 世界观/人物志/笔耕保存前，LLM 判定本页批注与修改的有效性并评估对全文影响，二次确认后才落库；确认前记录快照/版本历史，支持逐级撤回
- **版本历史与撤回** — 编辑前快照 + 前后端格式转换，支持连续撤回历史版本（显示剩余次数）
- **编辑经验沉淀** — 各环节保存修改自动采样（diff 定位变化区），批注与修改经 LLM 判定有效性后沉淀为写作经验（带来源 scope），注入后续审查 prompt
- **墨韵（文风 + 审校 + 规则配置）** — 文风指标、反 AI 检查、一致性审校合一页；反 AI 味规则（五类词表/计分/「语言铁律」提示词）可在线编辑，保存后立即带入写作、审查、批注重写工作流
- **反 AI 味检测** — 规则化标准（套话/弱化副词/书面连接词/意义膨胀/情绪直说）0-100 分，词表与计分全局可配
- **细纲展开** — 情节脉络节点「全部展开」由后台任务自动续展到全部章节，批间携带已展开细纲保证剧情连续；切换页面后自动恢复进度，可中途取消、已展开部分保留
- **智能分卷** — 大纲页按基础设定的预计卷数把全部章节均分到「第一卷 / 第二卷…」，每卷可折叠、内含章节细纲；未设卷数时保留导入的卷名
- **字数硬约束** — 章节正文严格控制在目标字数 ±15% 区间（写作与审查双约束 + 引擎门禁），防止注水或内容不完整
- **版本与更新** — 侧边栏显示当前版本，点击可检查 GitHub 最新 Release 与更新日志；Windows 支持自动下载安装，macOS 引导前往下载页
- **三层蒸馏** — 专家蒸馏（人物思维 → 讨论评审员）、书籍蒸馏（写法 → 工作流技能卡）、方法论蒸馏（写作方法论 → 技能卡）
- **并发控制** — 乐观锁 + 操作队列 + 冲突检测，用户编辑与 AI 生成互不干扰
- **增量一致性检查** — 按范围（章节/卷/全书）增量扫描，5 条规则实时报告不一致项
- **LLM 模型适配** — 按模型自动匹配请求参数（推理开关/预算字段），统一调用、重试与降级；JSON 输出按报错位置驱动式修复，章节正文剥离规划文本与代码围栏

| 层级 | 技术 |

## 项目结构

```
├── Cargo.toml                 # Rust 工作空间（10 个 crate）
├── agent.md                   # Agent 强制工作约定
├── package.json               # 前端依赖与构建脚本
├── vite.config.ts             # Vite 配置
├── index.html                 # 前端入口
├── src/                       # 前端源码（React + TypeScript）
│   ├── components/            # 通用组件
│   ├── views/                 # 页面视图（创作台/笔耕/大纲/人物/世界/设定/工坊…）
│   ├── ipc.ts                 # IPC 封装（命令唯一入口）
│   ├── types.ts               # 前后端共享类型
│   └── store.ts               # 状态管理
├── crates/                    # Rust crate 集合（10 个）
│   ├── pensoul-core/          # 领域模型：四层本体、错误类型
│   ├── pensoul-harness/       # 确定性流程引擎（门控/WAL/崩溃恢复）
│   ├── pensoul-cda/           # 影响图与 BFS 变更传播
│   ├── pensoul-memory/        # 四层记忆系统
│   ├── pensoul-agent/         # Agent 双通道协议与预置定义
│   ├── pensoul-concurrency/   # 并发控制（版本/校验和/冲突）
│   ├── pensoul-consistency/   # 增量一致性检查（5 条规则）
│   ├── pensoul-llm/           # LLM 提供商适配与模型路由
│   ├── pensoul-import/        # 数据导入导出/备份
│   └── pensoul-app/           # Tauri 应用层：命令/管线/集成/受控保存/编辑经验
├── skills/                    # 蒸馏技能模板（Books/Experts/Methodology）
├── WritingCard/               # 方法论技能卡（本地产物）
├── tools/                     # 图标生成工具脚本
└── .github/workflows/         # 构建与发布流水线
```

> 注：`docs/`（架构、IPC 契约、工作进度等开发文档）与 `Experts/`（作者专家蒸馏素材）为本地开发产物，
> 不随代码仓库推送到 GitHub。

## 快速开始

### 前提条件

- Rust 2024 或更新版本
- Node.js 18+
- macOS（Tauri 开发环境）

### 构建与运行

```bash
# 构建所有 crate
cargo build

# 启动 Vite 前端开发服务器
pnpm dev

# 启动 Tauri 桌面应用
cargo tauri dev

# 运行全部测试
cargo test

# 代码检查
cargo clippy --all -- -D warnings
cargo fmt --all --check
```

### 生产构建

```bash
# 桌面端（macOS .dmg / Windows .msi/.exe）
cargo tauri build

# Web 版本（产物在 dist/）
pnpm build
```

## 下载与发布

每个版本发布到 [GitHub Releases](https://github.com/Cnkore007/PenSoul/releases)，包含：

- **macOS**：`.dmg` / `.app`
- **Windows**：`.msi` / `.exe`
- **Web**：`dist` 静态产物压缩包

版本号遵循语义化版本，**每次发版必须同步更新 [CHANGELOG.md](CHANGELOG.md)**。
