# PenSoul — AI 长篇小说创作平台

让引擎管流程，让模型管创作。

PenSoul 是一个面向网络文学作者和严肃小说创作者的 AI 写作工具，基于 Rust + Tauri 构建，解决 500 万字级别超长篇小说的一致性、长期记忆和协同编辑问题。

## 核心理念

主流 AI 写作工具把流程写在提示词里，建议 AI 按步骤来——但建议终究只是建议，AI 会跳步、会绕过一致性检查、会忘记伏笔。PenSoul 换了一条路：

| 维度 | 主流做法 | PenSoul |
|------|---------|---------|
| 流程控制 | 写在提示词里（建议） | 写在引擎的确定性逻辑里（约束） |
| AI 行为 | AI 自觉遵守，可跳步 | 引擎硬性驱动，不可绕过 |
| 质量保障 | 可选步骤 | 必经之路（门控放行） |
| 工作流 | 写死在代码里 | P0 硬编码编排，P1 声明式工作流模板 |

## 核心功能

- **Harness 引擎** — 确定性流程引擎，用 Stage/Gate/WAL 驱动创作流程，支持自动/人工/条件三种门控模式
- **工作流模板化** — 作品库全局模板库 + 项目引用分层；模板可增删执行环节（含章前策划），环节绑定模型与写作技法卡
- **章节连写管线** — 章前策划 → 写作 → 审查（异模型门控）→ 回灌自动连写，支持暂停/继续/停止；黄金三章硬门控（钩子/爽点子分数必达标）
- **四层记忆系统** — 热/温/冷/叙事四级记忆，8 步更新管道，预算按编辑模式分配（默认 8000 token）
- **CDA 一致性驱动架构** — 基于影响图的 BFS 传播，1000 章构建 < 50ms，修改后自动标记受影响章节
- **多 Agent 讨论** — 立论/交锋两轮交锋后，成果按维度并行提炼（地点时间线/设定规则/人物关系/情节脉络/共识分歧），跨维度冲突显式标记，未收敛分歧由独立裁判裁决，进度实时推送
- **全链路批注** — 笔耕行内/整章批注之外，细纲、脉络节点、人物志、世界观各实体均可批注（问题/修改建议/备注，字段级或实体级锚点）；侧边栏「批注中心」聚合全部待处理批注，可跨页跳转、就地采纳/拒绝
- **受控保存（保存并审核）** — 世界观/人物志/笔耕保存前，LLM 判定本页批注与修改的有效性并评估对全文影响，二次确认后才落库；确认前记录快照/版本历史，支持逐级撤回
- **编辑经验沉淀** — 各环节保存修改自动采样（diff 定位变化区），批注与修改经 LLM 判定有效性后沉淀为写作经验（带来源 scope），注入后续审查 prompt，越写越少犯同类错误
- **墨韵（文风 + 审校 + 规则配置）** — 文风指标、反 AI 检查、一致性审校合一页；反 AI 味规则（五类词表/计分/「语言铁律」提示词）可在线编辑，保存后立即带入写作、审查、批注重写工作流
- **反 AI 味检测** — 规则化标准（套话/弱化副词/书面连接词/意义膨胀/情绪直说）0-100 分，词表与计分全局可配，审查阶段按同一词表扣分
- **细纲展开** — 情节脉络节点一次点击自动展开全部逐章细纲（内部分批保证产出质量），可中途取消，已展开部分保留
- **三层蒸馏** — 专家蒸馏（人物思维 → 讨论评审员）、书籍蒸馏（写法 → 工作流技能卡）、方法论蒸馏（写作方法论 → 技能卡）
- **并发控制** — 乐观锁 + 操作队列 + 冲突检测，用户编辑与 AI 生成互不干扰
- **增量一致性检查** — 按范围（章节/卷/全书）增量扫描，实时报告不一致项
- **LLM 模型适配** — 按模型自动匹配请求参数（推理开关/预算字段），统一调用、重试与降级
- **LLM 输出容错** — JSON 按报错位置驱动式修复（漏逗号/尾逗号/裸键/字符串引号闭合/截断补全），章节正文剥离规划文本与代码围栏

## 技术栈

| 层级 | 技术 |
|------|------|
| 桌面框架 | Tauri 2.x |
| 后端语言 | Rust (edition 2024) |
| 前端 | React + TypeScript + TipTap |

## 项目结构

```
├── Cargo.toml                 # 工作空间定义
├── agent.md                   # Agent 强制工作约定（文档同步规则）
├── src/                       # 前端源码（React + TypeScript）
│   ├── components/            # 通用组件
│   ├── views/                 # 页面视图
│   ├── ipc.ts                 # IPC 封装（命令唯一入口）
│   ├── types.ts               # 前后端共享类型
│   └── store.ts               # 状态管理
├── crates/                    # Rust crate 集合（10 个）
│   ├── pensoul-core/          # 领域模型：四层本体、错误类型
│   ├── pensoul-harness/       # 确定性流程引擎（门控/WAL/崩溃恢复）
│   ├── pensoul-cda/           # 影响图与 BFS 变更传播
│   ├── pensoul-memory/        # 四层记忆系统
│   ├── pensoul-agent/         # Agent 双通道协议与预置定义
│   ├── pensoul-concurrency/   # 并发控制（版本/校验和/冲突）
│   ├── pensoul-consistency/   # 增量一致性检查（5 条规则）
│   ├── pensoul-llm/           # 模型路由（应用层未接入，见架构文档）
│   ├── pensoul-import/        # 数据导入导出/备份
│   └── pensoul-app/           # Tauri 应用层：命令/管线/集成/受控保存/编辑经验
├── skills/                    # 蒸馏方法论技能（Experts/Books）
├── Experts/                   # 专家蒸馏产物
├── tools/                     # 图标生成工具脚本
├── docs/                      # 设计文档
│   ├── ARCHITECTURE.md        # 架构总览
│   ├── WORKFLOW.md            # 创作全流程手册
│   ├── DEVELOPMENT.md         # 开发指南
│   ├── IPC-CONTRACT.md        # IPC 契约（前后端事实源）
│   ├── ANNOTATION-DESIGN.md   # 全链路批注与受控保存设计（含实施记录）
│   ├── EVOLVE-DESIGN.md       # AlphaEvolve 进化式创作优化方案
│   └── PROGRESS.md            # 工作进度日志（Agent 强制同步）
├── index.html                 # 前端入口
└── vite.config.ts             # Vite 配置
```

## 快速开始

### 前提条件

- Rust 2024 或更新版本
- Node.js 18+
- macOS（Tauri 开发环境）

### 构建与运行

```bash
# 构建所有 crate
cargo build

# 启动 Vite 前端开发服务器
npx vite dev

# 启动 Tauri 桌面应用
cargo tauri dev

# 运行全部测试
cargo test

# 代码检查
cargo clippy --all -- -D warnings
cargo fmt --all --check
```

### 前端构建

```bash
npx vite build
```

构建产物在 `dist/` 目录，Tauri 生产模式会使用该目录。

## 设计文档

文档存放在 `docs/` 目录，均对齐当前代码：

- **ARCHITECTURE.md** — 架构总览：crate 职责、管线、集成层、LLM 层、事件流
- **WORKFLOW.md** — 创作全流程手册：从萌芽讨论到造化工坊连写的完整链路
- **DEVELOPMENT.md** — 开发指南：构建/测试/规范/新增 IPC 三步
- **IPC-CONTRACT.md** — IPC 契约：全部命令与事件协议
- **ANNOTATION-DESIGN.md** — 全链路批注、编辑经验沉淀、受控保存的设计与实施记录
- **EVOLVE-DESIGN.md** — AlphaEvolve 调研与「进化脚手架，不进化正文」落地方案
- **PROGRESS.md** — 工作进度日志：每个 Agent 每轮工作必须追加记录

仓库根目录的 **agent.md** 是强制约定：无论换什么 LLM/Agent 工具，开工前必读
`docs/PROGRESS.md`，每轮工作后必须把进度、问题、设计思考写入其中，代码变更后
同步对应文档，防止文档与代码再次脱节。
